# Writing for the receipt, the pane and the documents

## Words

- Evidence, never proof. Tamper-evident, never tamper-proof.
- Never say a run was secure, safe, correct or compliant. Say which checks ran and passed, and what was not checked.
- Use the product words consistently: charter, stage, checkpoint, drift, restart, branch, ledger, receipt.
- Full forms and no apostrophes in prose and interface copy: do not, it is, cannot.
- Plain sentences. No marketing adjectives. No single trust score.

## The receipt, in this order

1. Job, dates, models, and the two verdicts, kept separate and never merged into one: stayed on course, and result verified. Then each success criterion with the check that verified it, or the words not verified. Then three to five statements of fact, each linked to its evidence. Example: "Stage 3 exceeded the scope threshold at checkpoint A4. The operator restarted from A3."
2. Charter and its versions.
3. Run map.
4. Stages with drift by dimension and checks.
5. Corrections: each restart with its reason and the rule it became.
6. Rule changes, with old and new scores for every re-scored checkpoint.
7. Actions that left the workspace, marked reversible or not.
8. Coverage statement: what Candor does not check.
9. Overhead: added time, tokens and cost.
10. Integrity: chain head, anchors, and the exact command to verify.
11. Limits.

## Rules for every screen and document

- Problems are as visible as progress. A flag is never hidden behind a tab or a collapsed section.
- Every flag opens the ledger entries behind it.
- Color is never the only signal. Pair it with a word or a shape.
- Every number in a document comes from `results/`. If a number is not measured yet, write "to be measured".
- A recorded run is labelled live or scripted, with date, model IDs and cost if live.
- State what a competitor or an existing feature does before saying what this does that it does not.
